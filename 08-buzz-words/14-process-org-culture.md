# Process, Org & Culture Buzzwords

[← Buzzwords index](README.md)

| Term | Meaning |
|------|---------|
| Agile | Iterative delivery with frequent feedback |
| Scrum / Kanban | Time-boxed sprints with roles / continuous flow with WIP limits |
| Backlog grooming / refinement | Clarifying and sizing upcoming work |
| Bus factor | How many people can leave before project stalls |
| Cognitive load | Mental effort a team carries; platform teams reduce it |
| Definition of Done | Agreed criteria for "finished" |
| Design doc / RFC | Written proposal reviewed before building |
| Developer portal (Backstage) | Catalog + templates + docs for internal services |
| Eat your own dog food | Use what you build |
| Five whys | Ask "why" repeatedly to find root cause |
| InnerSource | Open-source practices inside a company |
| IDP | Internal Developer Platform: self-service infra for devs |
| ITIL | IT service management framework (incidents, changes, problems) |
| KTLO | Keep the lights on: maintenance work |
| North star metric | One metric capturing core value |
| OKRs | Objectives and Key Results goal framework |
| Postmortem | Incident review document |
| RACI | Responsible, Accountable, Consulted, Informed |
| Retrospective | Team reflects on what to improve |
| Shift-left culture | Devs own testing, security, ops early |
| Sprint | Fixed iteration (1–2 weeks) |
| Stakeholder | Anyone affected by or influencing the work |
| Story points | Relative effort estimate |
| Team Topologies | Stream-aligned, platform, enabling, complicated-subsystem teams |
| Tech radar | Map of adopt/trial/assess/hold technologies |
| Thinnest viable platform | Smallest platform that removes real dev friction |
| "You build it, you run it" | Teams own their services in production |
| Two-pizza team | Team small enough to feed with two pizzas |
| WIP limit | Cap on concurrent work items |
| SPACE framework | Developer productivity: satisfaction, performance, activity, communication, efficiency |
